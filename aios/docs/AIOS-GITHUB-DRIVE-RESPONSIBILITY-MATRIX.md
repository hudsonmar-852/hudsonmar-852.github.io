# AIOS GitHub–Drive Responsibility Matrix

Status: Draft pending `P-GOV-ALIGN-001`

| Category | Authority | Canonical location | Mirror rule |
|---|---|---|---|
| Governance, agent rules, registries | GitHub | `aios/governance/`, `AGENTS.md`, `aios/data/` | Drive executive copy labelled non-authoritative |
| Code, config, schemas, tests, CI, workflows | GitHub | repository paths | Never duplicate executable source in Drive |
| ADRs, EOs, technical architecture | GitHub | canonical map | Optional Drive executive copy |
| Dashboard and release definitions | GitHub | `aios/data/`, release records | Drive review/release pack only |
| Research, meetings, reports, knowledge | Drive | `Hudson AIOS` classified folders | Link from GitHub when needed |
| Large/media/private assets | Drive | approved private/project folders | No public mirror by default |
| AI communication | Drive | `Hudson AIOS/chatgpt_grok/` | Promote decisions into GitHub registries |
| Local checkout | MacBook | working copy | Never authority |
| Chat/memory | none | not applicable | Never approval or project record |

The Drive `AIOS_Master_v1.0` claim that it is the unique core specification
is partially aligned but conflicts with GitHub authority for governance and
technical records. The two same-named storage-architecture drafts also conflict.
They remain unmoved pending approval and should become historical/reference
copies after a reviewed migration.
